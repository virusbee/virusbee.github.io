# 网页复刻与 Build Log

## 一句话方法

**先找到真身，再列清单；先让内容成立，再让交互成立，最后才让视觉成立。**

复刻的终点不是“像”，而是“成立”：结构成立、数据成立、交互成立，最后才是视觉成立。

**适用：** 新增一期复刻、审查已有复刻、把复刻过程写成 Build Log、同步首页与 README。
**不适用：** 复刻登录、注册、二次验证与鉴权流程本身；后端逻辑、需要实时接口的功能。需要登录才能看到的页面不是禁区——先登录，再取源。也不要把他人的图片、数据与文案直接用于商业发布。复刻用于学习与研究，保留出处、作者与免责声明。

## 九条不变量

1. **复刻规则，不复刻像素。** 提取层级、间距节奏、颜色关系、动效时长和信息组织方式，而不是某一帧截图。
2. **需要登录，先登录。** 登录墙后面的页面，未登录不取源、不猜内容、不伪造 Cookie；登录由用户本人在真实浏览器完成，凭据不进对话、不进脚本、不进交付物。
3. **先找 iframe 真身。** 顶层页面往往只是登录壳，真正内容在独立子页面里。
4. **内容清单先于样式。** 先列条目、分组、字段、链接、日期，再写 CSS；视觉可以重画，内容不能凭印象补。
5. **数据成立才叫复刻。** 合计、占比、涨跌、坐标、日期、外链必须自洽；不编造数字，不删免责声明。
6. **动效是增强，不是门槛。** 内容默认可见；隐藏只在 JS 主动授权后生效；减弱动效、无 JS、打印都能恢复内容。
7. **移动端是重排，不是缩小。** 表格转卡片、侧栏转底部抽屉、画布重算视口；320px 也要能读、能点、无横向滚动。
8. **单文件交付，站点共享规范。** 复刻页自包含、可独立打开；文章与首页共用同一套视觉 Token 和写作结构。
9. **验收靠测量，不靠目测。** `scrollWidth`、逐元素右边界、截图、控制台、网络、打印、确定性导出都是验收的一部分。

补充两条底线：

- **不遮问题。** 原页面有 bug 就修，并写清“修复前 / 修复后”；不要把 `overflow-x:hidden` 当成溢出修复。
- **未经明确要求不 commit / push。** 交付时保持工作区改动可见，让用户自己决定提交时机。

## 标准流程

### Phase 0 — 立项与边界

先写清这次复刻的“成立条件”：保留哪些内容与数据、哪些交互必须可用、哪些明确不做、验收看哪几个视口、交付物有哪些。记录原始页面的元信息（URL、保存时间、原始大小/行数、外部依赖、内容规模、关键数据）。

**准入门槛：源页面需要登录的，先确认能登录再往下走。** 拿不到账号就换源或换案例，不要靠猜内容硬写。命名固定为：

```text
replicas/replica_0X.html
posts/how-i-replicated-<slug>.html
```

文章标题统一为“我如何复刻 X”，slug 用英文短横线，Build Log 编号与案例编号一致。发布前做一次脱敏检查：金额、姓名、账号、精确位置、截图中的昵称与头像。

### Phase 1 — 登录并拿到原始页面

适用于需要取源的新案例；纯视觉重建的案例可跳过。

**先判断是否需要登录。** 打开 URL 后只看到登录卡片、被跳到 `/login` 之类的路由，或者页面是一层空壳，就说明后续流程必须建立在已登录状态上。此时不要继续猜内容，也不要用匿名抓取硬取。

登录四条规则：

1. **由用户本人登录。** 用浏览器控制打开页面，请用户自己输入账号密码、扫码或完成二次验证；不要向用户索要密码与验证码，也不要把 Cookie、Token 写进对话、脚本或任何交付文件。
2. **登录后再取源。** 登录完成后沿用同一浏览器会话（同一上下文与 Cookie）继续操作，不要在另一个会话里重新打开页面。
3. **不做绕过。** 不伪造 Cookie、不改请求头冒充身份、不绕验证码与访问控制。没有权限就停下，请用户提供可公开访问的源，或换一个案例。
4. **登录状态不进产物。** 复刻页不得包含真实账号、会话信息、头像昵称；只有登录后才能拿到的接口数据（地图 key、私有接口）在静态化后必然失效，要写进文章的“已知限制”。

进入内容页后，触发隐藏在弹窗、抽屉或登录壳后面的内容（本项目的案例多来自 WorkBuddy 成长中心的弹窗 iframe），再从控制台列出 iframe：

```js
[...document.querySelectorAll('iframe')].map(f => f.src)
```

也可以从 Elements 选中 iframe，或从 Network 筛 `output.html`。直接打开子页面，确认内容完整、能独立访问，再保存原始文件并记录字节数与行数。检查 `http://`、`https://`、`<script src>`、`<link href>`；能独立打开、零外部依赖的原作最理想。判断标准：直接打开保存后的文件，正文、数据、交互都在，才算拿到真身。

### Phase 2 — 拆骨架与内容清单

先画矩形，不要先调颜色。典型四层结构：固定顶栏/终端栏 → Hero → 内容区（分类头 + 卡片/时间线/表格/地图）→ Footer。找出唯一重复单元，重复单元确定后 CSS 才写得稳。

同时建立可校验的内容清单：条目数、分组数、字段数、合计、占比、坐标、日期。清单尽量从 DOM 或内嵌 JSON 提取，不要手抄。校验规则写成不变量，例如“各组条目数之和 = 总数”“轨迹终点与 `endPoint` 对齐”“同 Seed 同视口导出像素一致”。

### Phase 3 — 提取设计 Token

先抽 8–12 个变量，再拼组件。颜色、字体、间距、圆角、阴影、动效时长都进 Token。边框优先用强调色的透明版本，换主题色时描边自动跟随；中文正文用系统 sans，编号/时间/来源/导航用 mono；字号差距不必很大，靠字重、颜色、等宽字体建立层级。做一次“关掉强调色”测试：如果页面立刻失去层级，说明结构还不够。

可直接从 `assets/tokens.css` 取起点，按案例改值，不要在每个组件里重复硬编码。

### Phase 4 — 实现页面

顺序固定为：**结构 → 间距 → 颜色 → 字体 → 动效**。每完成一步截图对比，避免一次改太多变量。语义骨架至少包含 skip-link、header、main、footer；标题用 `text-wrap: balance`，但长英文/公式必须同时有 `overflow-wrap: anywhere`，网格/弹性子项加 `min-width: 0`。

单文件取舍：HTML/CSS/JS 全部内联；图片优先内嵌 WebP；小图标用内联 SVG；不加载外部字体。复刻页可以自包含，但视觉 Token、文章模板、首页样式要与站点保持一致。不要为了“单文件”牺牲可读性：该分函数就分函数，该写注释就写注释。

### Phase 5 — 数据、状态与确定性

这是复刻和“照着画”差距最大的地方。

- **报告/信息流：** 数据用对象或内联 JSON 管理，渲染函数只负责排版；合计、占比、涨跌颜色必须能对上，`+/-` 不能只靠颜色表达；双语切换同步 `document.title`、区块标题、表头、条目名称、免责声明和 `html lang`；打印保留数据，隐藏浮动操作栏和装饰。
- **地图：** 轨迹若是增量编码，先确认顺序，用终点误差验证解码，而不是“看起来像”；站点、轨迹、底图必须使用同一套 Web Mercator 投影；底图按内容包围盒反推瓦片范围，构建时预渲染并内嵌；移动端用安全区约束标签和弹窗。OSM 底图必须保留 `© OpenStreetMap contributors` 与 ODbL 说明，控制批量抓取，商业用途换授权底图。
- **Canvas/生成艺术：** 只用 seeded PRNG 接管噪声置换与粒子随机流；Seed 可通过 URL 传入、显示、复制；`resize` 不重新生成，先快照再缩放粒子坐标；DPR 上限 2；暂停后像素完全不变；导出前先停一帧；减弱动效下渲染静帧而不是空白。

确定性自测以**像素哈希**为准，不以 PNG 字节为准：同 Seed + 同视口 + 同 DPR + 同 resize 历史 + 同帧数 → 像素哈希一致；换 Seed 明显不同；暂停后连续截图无差异。不要把基于 `dt` 的时间积分混进固定步进动画。

### Phase 6 — 交互与动效

只保留三类动效，每类只做一件事：

| 类型 | 作用 | 参考参数 |
|---|---|---|
| 数字滚动 | 把“统计”可视化 | 1.1s，easeOutCubic |
| 滚动入场 | 建立阅读顺序 | 0.48s，错峰 28ms |
| 状态过渡 | 悬停、抽屉、弹窗 | 0.2–0.25s |

内容默认可见；不要用全局 `.js .reveal{opacity:0}`，因为主脚本一旦报错，正文会永久隐藏。正确做法是由 JS 给需要动画的元素加 `.js-reveal`，再由 `IntersectionObserver` 加 `.visible`，并在 `load` 后设置超时兜底。减弱动效时必须复位 `scroll-behavior`，并让 `.js-reveal` 直接可见。完整规则见 `assets/reveal.css`。

键盘与可访问性：画布 `Space` 暂停/恢复，但焦点在按钮上时不劫持；地图 `Escape` 关弹窗/退出聚焦，`+` / `-` / `0` 缩放与重置；所有交互控件可 Tab 到达，`:focus-visible` 清晰可见；图表补 `role="img"`、`<title>`、`<desc>` 或文字等价物；装饰图标 `aria-hidden="true"`；切换按钮用 `aria-pressed`，语言切换同步 `lang`。

### Phase 7 — 响应式

断点由内容决定，不要按设备名拍脑袋。常用断点：900px（多列 KPI/卡片收缩）、820px（地图左面板转底部抽屉）、700px（文章移动布局）、560px（五列表格转卡片）、480px（首屏 meta 改竖排）、375px/320px（最终窄屏验收）。

表格转卡片，不是隐藏列；点击区域不小于 44px；底部抽屉、弹窗不越界；320px 下检查 `documentElement.scrollWidth === 320`，并用逐元素右边界检查兜底，因为 `overflow-x:hidden` 会让 `scrollWidth` 说谎。不要用 `overflow-x:hidden` 掩盖溢出，先找到真正超宽的元素。画布 resize 时先快照，再按 `sx = width/oldW`、`sy = height/oldH` 同时缩放 `x/y` 与 `prevX/prevY`，重置 `ctx.setTransform(dpr,0,0,dpr,0,0)` 并重绘背景。

### Phase 8 — 写 Build Log

文章不是流水账，而是“问题 → 尝试 → 证据 → 修复”的记录。固定结构见 `references/build-log.md`：Hero + 8 个编号章节 + CTA + Footer。每个判断尽量带数字；代码只贴能说明一个决定的关键片段；对比用表格，趋势用图表，界面用截图，每张图都有说明；原页面有缺陷时写“修复前 / 修复后”；文章要能独立阅读。

### Phase 9 — 更新首页与 README

首页新增卡片时，同时同步 Hero 篇数、`Total Logs` 的 `data-target` 与显示值、`--latest` 数字、`Latest` 日期、分类计数、饼图无障碍文本、页脚篇数、meta description、README 文章列表与 Demo 列表。完整清单见 `references/site-sync.md`。

不要手工改十几处：先更新 `assets/cases.json`，再运行：

```bash
python3 .agents/skills/workbuddy-replica/scripts/sync_site.py --check
```

脚本只校验/修复计数类字段；新卡片仍需按最新在前手工插入。

### Phase 10 — 验收

先跑静态检查，再跑视口与功能验收：

```bash
python3 .agents/skills/workbuddy-replica/scripts/check_site.py --root .
node .agents/skills/workbuddy-replica/scripts/audit_viewport.mjs --url http://localhost:8000 --out .audit
```

静态检查覆盖站内链接、锚点、图片、`srcset`、`script/link`、重复 ID、`lang`、`title`、meta description、图片 `alt`、外链 `target/rel`。视口至少覆盖 1440×900、1024×768、768×900、656×900、560×800、375×812、320×700；每档测 `scrollWidth`、逐元素右边界、控制台错误并截图。功能项、打印、性能与完整 DoD 见 `references/acceptance.md`。

## 交付门槛

- 复刻页可独立打开，无构建步骤，无外部依赖或依赖已内嵌。
- 内容、数据、链接、免责声明完整，无编造；发布内容已脱敏，不含 Cookie、Token、真实账号与真实头像昵称。
- 1440/1024/768/656/560/375/320 无横向溢出。
- 键盘可完成主要操作，焦点可见；减弱动效下内容可见；无 JS 时正文仍可读。
- 打印不丢内容、不出现色块；Console 无 error，Network 无 404。
- 文章 Hero、TL;DR、8 章、验收表、复盘、CTA 完整；图片加载、图表有标题/描述。
- 首页 KPI、`--latest`、饼图、分类计数、页脚、meta、README 全部同步。
- 临时测试文件已清理，本地服务器已停止，`git status` 改动清晰可见。

## 最后记住

复刻不是把页面抄一遍，而是把原页面的每个决定重新验证一遍：哪些该保留？哪些是当时的妥协？哪些其实是 bug？把这三件事分开看，复刻才会从“像”走到“成立”。已有案例的具体数字与踩坑记录见 `references/cases.md` 与 `references/pitfalls.md`。
