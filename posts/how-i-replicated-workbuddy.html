我如何复刻 WorkBuddy 灵感社区

一次对 WorkBuddy 视觉语言的完整拆解：如何从页面里提取结构、颜色与节奏，再把它变成可运行的 HTML / CSS / JS。文末附复刻 Demo。

做这个主页时，我想找一种既能保持开发者气质、又不会让内容显得冷冰冰的视觉语言。最后我选了 WorkBuddy 灵感社区的深色终端风：固定顶栏像终端窗口，主视觉用网格与光晕铺底，内容以情报卡片的方式排列。

这个仓库里的 workbuddy_replica_01.html 就是那次复刻的结果——一份包含全部样式与交互的单文件页面。下面是我拆解和实现它的过程。当然本页面的风格也是据此实现的。

TL;DR

复刻的核心不是抄像素，而是提取规则：颜色之间的关系、间距的节奏、动效的时长、信息的层级。骨架对了，细节自然会长出来。

01先拆骨架，再谈还原

复刻最怕一上来就调颜色。第一步应该把页面还原成几个矩形：哪些部分是固定的，哪些会随内容增长，哪些元素会重复出现。

拆完之后，页面其实只有四层：

  • 终端栏：sticky 固定在顶部，包含三色窗口灯、命令行提示符和分类导航。
  • Hero：一句带渐变的标题、一段说明，以及四张 KPI 卡，其中一张嵌入分类分布环图。
  • Dashboard：分类标题 + 重复出现的情报卡片，是页面的内容主体。
  • Footer：来源、计数与版权信息，为页面收尾。

一旦找到重复单元，CSS 就好写了。卡片只有一种，分类头只有一种，剩下的都是间距与内容差异。

index.html 
<div class="terminal-bar">…</div>
<header class="hero">…</header>
<main class="dashboard">
  <section class="category" id="model">
    <div class="category-head">…</div>
    <div class="intel-list">…</div>
  </section>
</main>
<footer>…</footer>

我给自己定的顺序是：结构 → 间距 → 颜色 → 字体 → 动效。每完成一步都截图对比，避免一次性改太多变量。

02把视觉语言翻译成 Token

WorkBuddy 的深色不是纯黑，而是带一点蓝的深灰；高亮也不是常见的蓝紫，而是偏青的薄荷绿。把这类观察写成变量，页面才不会在迭代中走样。

TokenValue用途
--bg-primary#0F1115页面底色
--bg-card#1B202B卡片 / 标签底
--bg-elevated#222938卡片悬停
--text-primary#F3F7FA标题
--text-secondary#AAB7C4正文
--text-muted#697789元信息
--accent#00D9A3强调 / 链接
--accent-2#7CFFCB渐变高光
--borderrgba(124,255,203,.14)默认描边
--border-hoverrgba(124,255,203,.36)悬停描边

这里有一个关键细节：边框没有使用单独的灰色，而是强调色的透明版本（14% 和 36%）。这样即使换成别的主题色，整套描边也会自动跟着变，不会出现两种色温打架的情况。

style.css 
:root {
  --bg-primary: #0F1115;
  --bg-card: #1B202B;
  --text-primary: #F3F7FA;
  --text-secondary: #AAB7C4;
  --accent: #00D9A3;
  --accent-2: #7CFFCB;
  --border: rgba(124, 255, 203, 0.14);
  --border-hover: rgba(124, 255, 203, 0.36);
  --font-sans: -apple-system, "PingFang SC", sans-serif;
  --font-mono: "SF Mono", Menlo, Consolas, monospace;
}

字体分工同样重要：标题和正文使用系统 sans，保证中文阅读；编号、时间、来源、导航使用 mono，负责制造“终端感”。两者混排，才有工具界面和信息面板的味道。

一个很实用的检查方法：把强调色关掉，页面是否还成立？如果全部靠绿色撑着，说明层级还不够。

03用 CSS 搭出终端氛围

背景是第一层氛围。纯色会显得平，我用了两张 36px 的网格线叠加两层径向光晕：左上偏绿，右上偏蓝，既打破单调，又把视线推向内容。

style.css 
body {
  background-color: var(--bg-primary);
  background-image:
    linear-gradient(rgba(124,255,203,.03) 1px, transparent 1px),
    linear-gradient(90deg, rgba(124,255,203,.03) 1px, transparent 1px),
    radial-gradient(circle at 20% 0%, rgba(0,217,163,.12), transparent 34%),
    radial-gradient(circle at 85% 15%, rgba(97,165,255,.08), transparent 28%);
  background-size: 36px 36px, 36px 36px, 100% 100%, 100% 100%;
}

顶部终端栏的关键词是“固定但不厚重”：92% 不透明度的深色底，加上 14px 的 backdrop-filter，让滚动时内容从底下若隐若现。三个红黄绿圆点几乎是终端视觉的暗号，成本极低，辨识度很高。

标题的渐变不用图片，直接让背景渐变透过文字：

style.css 
.hero h1 span {
  background: linear-gradient(135deg, #00D9A3 0%, #7CFFCB 100%);
  -webkit-background-clip: text;
  -webkit-text-fill-color: transparent;
  background-clip: text;
}

卡片是出现频率最高的组件，所以值得多花时间。左侧 3px 强调条负责视觉锚点，悬停时整张卡片上浮 2px、边框变亮、加一层很淡的绿色辉光。幅度都很小，但组合起来会让页面显得“活着”。

style.css 
.intel-card::before {
  content: "";
  position: absolute;
  left: 0; top: 0; bottom: 0;
  width: 3px;
  background: var(--accent);
  opacity: .6;
}

.intel-card:hover {
  border-color: var(--border-hover);
  background: var(--bg-elevated);
  box-shadow: 0 0 26px rgba(0, 217, 163, .08);
  transform: translateY(-2px);
}

信息密度也要克制：标题 1.02rem，摘要 0.9rem，元信息 0.72rem。字号差距不大，但通过字重、颜色和等宽字体建立层级，而不是不停放大标题。

04让交互跟着内容呼吸

页面里只有三类动效，各自负责一件事。

第一类：数字滚动。KPI 从 0 增长到目标值，用 easeOutCubic 在 1.1 秒内完成。它不是为了炫技，而是把“统计”这个动作可视化。

app.js 
function animateNum(el, target, duration) {
  const start = performance.now();

  function tick(now) {
    const progress = Math.min((now - start) / duration, 1);
    const eased = 1 - Math.pow(1 - progress, 3);
    el.textContent = Math.round(eased * target);
    if (progress < 1) requestAnimationFrame(tick);
  }

  requestAnimationFrame(tick);
}

第二类：滚动入场。卡片初始下移 14px 并透明，进入视口后恢复；同一批出现的卡片间隔 28ms，形成轻微的顺序感。每个元素只触发一次，回滚时不会反复闪烁。

app.js 
const cardObserver = new IntersectionObserver(entries => {
  entries.forEach((entry, index) => {
    if (!entry.isIntersecting) return;
    entry.target.style.transitionDelay = (index % 8) * 28 + "ms";
    entry.target.classList.add("visible");
    cardObserver.unobserve(entry.target);
  });
}, { threshold: 0.12 });

第三类：导航定位。用 IntersectionObserver 在视口上方 35% 到下方 42% 之间留出一条“检测带”，哪一段进入这条带，对应的导航项就亮起。它比监听 scroll 事件更轻，也更准确。

app.js 
const spy = new IntersectionObserver(entries => {
  entries.forEach(entry => {
    if (!entry.isIntersecting) return;
    links.forEach(link => {
      const active = link.getAttribute("href") === "#" + entry.target.id;
      link.classList.toggle("active", active);
    });
  });
}, { rootMargin: "-35% 0px -58% 0px" });

最后是悬停细节：链接箭头向右上移动 2px，卡片上浮 2px，过渡统一用 250ms 的 cubic-bezier(0.4, 0, 0.2, 1)。动效时长统一，页面才会有自己的节奏。

另外在首页补了一条 prefers-reduced-motion：当用户系统设置减少动态效果时，直接显示最终状态。复刻是视觉练习，但不应该以牺牲可用性为代价。

05响应式是重排，不是缩小

我只设了两个断点，因为结构本身不复杂。

  • 900px：KPI 从四列变两列，导航隐藏，卡片编号列从 52px 收窄到 42px。
  • 560px：KPI 变成单列，卡片改为单列布局，Hero 与内容区收窄内边距，分类头允许换行。

标题使用 clamp(2.4rem, 6vw, 4.6rem)，让它在手机和宽屏之间自然缩放，不需要为每个尺寸单独写字号。

移动端的目标不是一模一样，而是同样清楚：标题不挤、正文可读、点击区域够大。把桌面版硬塞进 375px 的屏幕，只会得到一个缩小的、不可用的桌面版。

06为什么最后是单文件

把 HTML、CSS、JS 全部放进一个文件，是一个很实际的取舍。

  • 优点：零构建、零依赖，双击就能看，直接丢进 GitHub Pages 就能上线；分享给别人时只需要一个文件。
  • 代价：设计 Token 会在页面间重复，样式规模变大后难以复用，团队协作也不友好。

当站点只有一页时，单文件是优势；当它开始有第二篇、第三篇文章时，就应该把公共部分抽出来。这个主页保留了同样的思路：每一页都自包含、可独立阅读，同时共用一套视觉 Token。

07复盘：1:1 不是像素复制

做完之后，我对“1:1 复刻”的理解变得更具体了：真正要复刻的是规则，而不是某一帧画面。

  • 结构上，能找到重复单元，并让内容可以无限增长。
  • 颜色上，所有层级来自同一组变量，换主题色不会崩。
  • 排版上，字号、行高、间距有固定节奏，而不是逐段手调。
  • 交互上，动效服务于信息，不抢内容。
  • 工程上，页面可以直接打开、部署和分享。

如果接下来继续迭代，我会优先做三件事：把公共样式抽成共享文件、补上文章模板与标签归档、继续打磨键盘导航与移动端细节。

如果你也想复刻一个喜欢的网站，建议从一张截图开始：标出所有重复模块，写下 8 个颜色变量，然后只做第一屏。第一屏立住了，后面会快很多。
