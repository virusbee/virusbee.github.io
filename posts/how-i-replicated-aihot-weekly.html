SECTION 00

摘要
00

先读结论

Build Log 003

这篇的起点和上一篇一样，也是一个 iframe。但难点不在 iframe，而在内容密度：24 篇论文、7 个日期分组，每篇都有来源徽章和原文链接。任何一处省略，都会让「一周盘点」失去意义。

我给自己定的验收标准有四条：桌面端看起来像原页面；移动端比原页面更成立；无 JavaScript 也能读到全部内容；打印出来不出现莫名其妙的色块。听起来是四件事，其实是同一件事——把内容从装饰里解耦出来。

TL;DR

先确认正文在哪个 document 里；用清单守住 24/24 的完整性；把动效做成可关闭的增强；最后拿原页面的移动端缺陷逐项对照。复刻不是照抄，而是重新负责。

原页面的标题是「AI HOT — 一周 AI 论文盘点 · 2026-05-02 ~ 2026-05-09」。我先记下这个日期区间，因为它决定了后面所有分组的顺序：盘点可以重排视觉，但不能打乱时间。

SECTION 02

24 篇，一篇都不能少

完整性优先于视觉

这类页面最容易被低估的工作，是「确认没有漏」。截图看起来差不多，不代表标题、摘要和链接都对。我把原页面里的条目逐条列成清单，再用脚本从 DOM 里取数比对：

分组数量这一行看起来很笨，但它是最有效的自检：7 个日期组加起来的条目数必须等于 24。只要有一个分组少了一篇，这里就会露馅。

摘要不改写只做排版，不做摘要
链接可点全部指向原文，新窗口打开

来源保留9+ 个徽章没有合并

外链统一加 target="_blank" 和 rel="noopener noreferrer"。摘要保持原文，不做二次概括——这是对原作者的尊重，也让「盘点」真的可以当作索引来用。

颜色与字体
03

从原页面提取设计 Token

先定颜色，再写组件

原页面的视觉语言很统一：浅蓝底、亮蓝主色、青色点缀，标题用衬线体，正文用系统无衬线。复刻时我没有直接抄样式，而是先抽出 6 个 Token，再用它们拼组件。

组件最后只留下三种：论文卡片、来源徽章、日期时间线。时间线是整页的骨架——日期在左，论文在右，圆点把同一天串起来。把这三个单元做稳，24 篇内容只是重复填充。

Hero 标题特意保留了衬线字体："Iowan Old Style" → Baskerville → "Songti SC"。它和正文的无衬线形成对比，也让「一周论文盘点」更像一份可以慢慢读的编辑稿，而不是信息流。

SECTION 04

滚动入场
04

入场动效必须能降级

默认可见，增强才隐藏

时间线很适合做滚动入场：卡片从下方浮起，圆点依次亮起。但这类动画有一个前提容易被忽略——它只能建立在「内容本来就在」的基础上。第一版里，我把 opacity: 0 写进了默认样式，结果无头截图和打印预览直接丢内容。

首屏曾被动画藏起来已修复

早期版本以 opacity: 0 作为初始值，截图、打印和低性能设备都可能看到空白。现在页面先加 .js，隐藏只在 .js 下生效；减弱动效与 <noscript> 都会把卡片恢复为可见。

打印时渐变标题变蓝块已修复

原页面用 background-clip: text 做渐变标题，打印时文字颜色丢失，只剩一个蓝色矩形。打印样式里恢复纯色文字，并关掉装饰背景。

papers / progressive enhancement
/* 默认：内容始终可见 */
.paper{opacity:1;transform:none}

/* 只有 JS 可用时才允许隐藏 */
.js .paper{opacity:0;transform:translateX(-12px)}
.js .paper.visible{opacity:1;transform:translateX(0)}

@media(prefers-reduced-motion:reduce){
  .js .paper{opacity:1!important;transform:none!important}
}

修复后的分工很明确：时间线负责节奏，卡片负责信息，动效只负责「出现得顺一点」。任何一层失效，内容都必须还在。

SECTION 05

窄屏修复
05

原页面留下的移动端 bug

响应式不是等比缩小

这次复刻有一个额外任务：原页面在桌面端是成立的，但窄屏下有几处明显的破绽。我把它们当成需求的一部分，而不是「照抄就算完成」。

移动端问题与修复
问题根因修复
时间线圆点被拉成椭圆 移动端把圆点改成 position: static 后，::after 的绝对定位改以 .day-rail 为包含块 恢复 position: relative; top: 0; left: 0
卡片标题被来源徽章挤压 标题缺少 min-width: 0，徽章又不换行 标题允许收缩换行，徽章移到独立一行
Hero 末字单独换行 衬线字体在窄屏下字符更宽，断行点落在最后一个字前 收紧字号 clamp，调整标题宽度与断行位置
timeline dot / mobile fix
/* 修复前：圆点脱离子元素，::after 以 .day-rail 为包含块 */
@media(max-width:768px){
  .day-rail .dot{position:static}
}

/* 修复后：保留定位上下文 */
@media(max-width:768px){
  .day-rail .dot{position:relative;top:0;left:0}
}

第一个问题最典型：position: static 本身没有错，错的是它悄悄改变了后代绝对定位的参照物。圆点里的 ::after 用 inset: 4px 画内圈，包含块一变，内圈就跟着整条时间线一起拉伸。

修复只改了两行 CSS，但前提是愿意打开开发者工具，顺着 computed style 找到真正的包含块。如果只对着截图调，很容易误以为是圆角或宽高写错了。

SECTION 06

验收
06

六档视口与打印验收

scrollWidth 比肉眼可靠

验收不是把浏览器窗口拖窄一点看看。我先用固定宽度的 iframe 逐个加载复刻页，读取 scrollWidth 和 clientWidth，再记录整页高度。六档视口的结果如下：

六档视口验收结果
视口页面高度布局变化结果
1440px约 6,430px桌面布局，日期时间线在左无溢出
768px—单栏，日期组改为上下排列完整可见
683px—移动布局，日期徽章置顶无溢出
560px—卡片单列，来源徽章换行无溢出
375px约 10,367px手机布局，圆点恢复正常无横向滚动
320px约 11,562px最窄验收，标题断行调整无横向滚动

页面高度从 1440px 的约 6,430px 增长到 375px 的约 10,367px、320px 的约 11,562px，这是正常的内容重排，不是问题。真正要盯住的是横向：每一档都必须满足 scrollWidth ≤ clientWidth。

打印是另一套视口。复刻页与文章页都按「能读」验收，文章页这边尤其要检查：

隐藏顶栏与目录只保留正文与页脚
标题恢复纯色不再出现渐变蓝块
卡片避免跨页break-inside: avoid
链接与来源可读页脚署名保留

打印稿里最容易被忽略的是颜色：屏幕上的渐变文字依赖背景裁剪，打印机不认这套。把这些效果在 @media print 里主动关掉，比事后解释「打印出来本来就会这样」要负责得多。
