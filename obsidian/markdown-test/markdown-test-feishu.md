# 飞书文档 Markdown 兼容性测试

> **一句话结论先看**：飞书用的是**自定义方言**，不是 CommonMark。最需要盯三处——`~单波浪~` 是下划线（不是删除线）、标题支持 **9 级**（不是 6 级）、公式用 `$$...$$`。
> 把别的编辑器写的 .md 粘进飞书，最容易在这三处走样。

---

## 0. 怎么测

三条路径还原度不一样，建议 **A + B 各跑一遍**，结果填进最后的记录表。

| 路径 | 操作 | 特点 |
| --- | --- | --- |
| **A 逐行输入** | 在飞书文档里手动敲语法 | 最贴合官方语法表，用于确认「语法本身对不对」 |
| **B 整篇粘贴** | Cmd/Ctrl + **V** 普通粘贴 | 批量识别，能额外识别表格、链接等，但可能部分转纯文本 |
| **C 导入文件** | 云文档 → 导入 → `.md` | 还原度通常低于粘贴；若无此入口则跳过 |

**三个必须知道的坑：**

1. 必须用**普通粘贴**。用「粘贴为纯文本」（Cmd+Shift+V）不会触发任何转换，整篇会变成一堆 `#` `**` 符号。
2. 官方语法表里，`**加粗**`、`*斜体*` 等**后面要求跟一个空格**才触发转换。逐行输入没问题，但批量粘贴时尾部空格容易丢——所以**粘贴后加粗不生效是这个原因，不是文件写错了**。
3. 飞书**移动端不支持查看 Markdown 语法**。手机打开这份文档，如果还看见 `##` `**`，说明没渲染成功，别怀疑手机坏了。

> 在飞书文档内按 `Cmd/Ctrl + /` → 下滑到 Markdown 小节，可随时调出官方语法表对照。

## 1. 基础项：官方语法表列明的（应当全部通过）

### 1.1 标题 1–6 级

# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

> 语法：`#` ~ `######` + **空格** ｜ ✅ 官方支持

### 1.2 标题 7–9 级（飞书特有，标准 Markdown 没有）

飞书支持到 9 级。请手动**逐行输入**下面三行（不要粘贴，粘贴后其他编辑器可能吃掉多余 `#`）：

```
####### 七级标题
######## 八级标题
######### 九级标题
```

> 语法：最多 9 个 `#` + 空格 ｜ ✅ 官方明确说明 ｜ 标准 Markdown 只到 6 级，第 7 个 `#` 会退化成字面文本

### 1.3 加粗 / 斜体 / 删除线

**这是加粗文本**

*这是斜体文本*

~~这是删除线文本~~

> 语法：`**文字**`、`*文字*`、`~~文字~~`，**后跟空格触发** ｜ ✅ 官方支持

### 1.4 下划线 ⚠️ 重点差异

~这是下划线文本~

> 语法：`~文字~`（**单**波浪号）｜ ✅ 官方支持 ｜ **坑**：标准 Markdown / GFM 里单个 `~` 要么是删除线、要么是下标，唯独飞书当成下划线。这是跨编辑器迁移时最典型的错乱来源。

### 1.5 有序 / 无序 / 任务列表

1. 有序列表第一项
2. 有序列表第二项
3. 有序列表第三项

- 无序列表第一项
- 无序列表第二项

- [x] 已完成任务
- [ ] 未完成任务

> 语法：`1.` + 空格、`-` 或 `*` + 空格、`[]` + 空格 ｜ ✅ 官方支持 ｜ 任务列表官方写法是 `[] 空格`，但实际 `- [ ]` 也常能识别，两种都试

### 1.6 缩进（Tab）

- 一级
	- 二级（Tab 缩进）
		- 三级（两个 Tab）

> 语法：`Tab` 增加缩进，`Shift + Tab` 减少 ｜ ✅ 官方支持 ｜ 注意飞书靠 Tab 而非 4 空格控制层级

### 1.7 引用

> 这是一段引用。
> 引用可以连续多行。

> 语法：`>` + 空格 ｜ ✅ 官方支持

### 1.8 行内代码与代码块

行内代码：`const answer = 42;`

```
无语言标记的代码块
  保留缩进与空格
```

```javascript
// 带语言标记，检查是否高亮
function greet(name) {
  return `Hello, ${name}!`;
}
```

> 语法：`` `代码` ``、```` ``` ```` + 空格 ｜ ✅ 官方支持 ｜ 重点看：语言标记是否被识别、代码块是否有复制按钮、是否支持行号

### 1.9 公式

$$E = mc^2$$

$$\int_{-\infty}^{\infty} e^{-x^2}\,dx = \sqrt{\pi}$$

> 语法：`$$文字$$` ｜ ✅ 官方支持 ｜ **坑**：标准 Markdown 里 `$$...$$` 是**块级**公式、`$...$` 是行内。飞书官方只列了 `$$`，行内 `$x^2$` 能否识别需实测

### 1.10 分隔线

---

> 语法：`---` 或 `***` ｜ ✅ 官方支持

## 3. 符号冲突专项（本文件最有价值的一节）

把同一条文本分别喂给飞书和标准编辑器，观察结果差异。**这一节决定你的 .md 能不能在团队里互通。**

| 语法 | 标准 Markdown / GFM | 飞书 | 风险 |
| --- | --- | --- | --- |
| `~文字~` | 删除线（GFM）或下标（Pandoc） | **下划线** | 🔴 高 |
| `~~文字~~` | 删除线 | 删除线 | 🟢 一致 |
| `$x^2$` 行内公式 | 行内公式 | 官方只列了 `$$` | 🟡 待测 |
| `#######` 七级标题 | 字面文本 | 七级标题 | 🟡 单向往飞书可用 |
| `==高亮==` | 高亮（部分扩展） | 不识别 | 🟡 单向 |
| `- [ ]` 任务列表 | 任务列表 | 官方写 `[]`，实测可能都行 | 🟢 基本一致 |

**实测动作：**

1. 在**飞书**里逐行输入下面三行，看渲染成什么：
   1. `~一个波浪~`
   2. `~~两个波浪~~`
   3. `$x^2$`
2. 把同样三行粘进 **Typora / Obsidian / VS Code**，对比结果。
3. 记录：同一份文件在两处是否显示一致。

**跨平台安全写法建议（若团队混用工具）：**

- 下划线**不要用** `~x~`，改用飞书工具栏手动加，或干脆不用（保内容优先）
- 删除线统一用 `~~x~~`，三方都认
- 公式统一用 `$$...$$` 块级写法，避免行内 `$...$`
- 标题最深只用到 6 级，别用 7–9 级（飞书独有，导出别处会崩）
- 表格、图片在飞书里都建议**手动插入**，不要依赖粘贴

## 4. 飞书专有块对照（Markdown 表达不了，需手动测）

这些是飞书文档的强项，但**没有任何 Markdown 语法能描述**。搬文档进飞书时这部分必然要重做。

- [ ] **多维表格**：粘贴的普通 Markdown 表格不会自动变成多维表格，需手动「转为多维表格」
- [ ] **思维笔记 / 思维导图**：无语法入口
- [ ] **画板 / 流程图**：无语法入口
- [ ] **分栏**：无语法入口
- [ ] **折叠块**：无语法入口（`<details>` 不认）
- [ ] **@人**：`@姓名` 是否能触发提及
- [ ] **提及文档**：`[标题](飞书链接)` 粘贴后是否变成文档卡片
- [ ] **任务 / 待办**：任务列表项能否一键转「任务」
- [ ] **日程 / 投票 / 嵌入网页**：无语法入口
- [ ] **代码块主题**：代码块是否可切换高亮主题
- [ ] **评论锚点**：粘贴后原文的批注是否保留（预期：不保留）

> 结论预期：**结构能过来，富交互块过不来。** 迁移前先想清楚哪些块必须手工重建。

## 7. 迁移建议（给要搬运文档的人）

1. **先跑第 3 节符号冲突专项**，这是唯一会造成"内容语义错乱"的地方，其他都只是样式丢失。
2. 粘贴前把源文件里的 `~x~` 全部改掉，否则到飞书会变成一堆莫名下划线。
3. 表格如果超过 6 列，建议到飞书后重建（或用多维表格），别指望粘贴完美。
4. 图片一律在飞书内重新上传，外链图不保证可访问。
5. 迁移完成后**在手机上打开看一眼**——移动端不渲染语法，残留的 `##` `**` 会立刻暴露问题。
